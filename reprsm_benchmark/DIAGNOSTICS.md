# 失败原因与已解决的输入问题

`no_certificate_found`、浮点 `optimal` 和精确 `proved` 是三种不同结果。当前实验没有把未经精确复核的浮点目标值当作概率上界。

## 1. 3DWalk：已解决的不变量检查性能问题

首版增加了由和断言推出的坐标盒上界。不变量在数学上有效，但三个实例均在求解器调用之前耗尽 60 秒进程预算。独立诊断栈定位到 `analysis/semantics.py:prove_nonnegative → sympy.solvers.simplex.lpmin → _simplex` 的精确 LP 迭代，见 [栈记录](runs/3dwalk_semantics_stack.txt)。这不是 MOSEK 超时。

最终版本移除这些冗余盒上界，仅保留坐标下界以及原程序的 `x+y+z<=1000` 断言。程序执行分布和目标事件保持不变。三个实例均成功，且证书已经独立重放：

| 初值 | 上界 |
|---|---|
| (100,100,100) | 0.3162503445378199 |
| (100,150,200) | 0.4725630557609795 |
| (300,100,150) | 0.5516264419721827 |

## 2. Rdwalk、2DWalk：数值失败背后的模板限制

实际运行记录为 `numerical_issue`；详细 MOSEK 日志报告 `Problem status: UNKNOWN` / `Solution status: UNKNOWN`，不是可靠的 infeasible 证明。例如 Rdwalk 的浮点解范数约 10^7、约束违反量约 2×10^-4；2DWalk 对应约 10^6 和 3×10^-4。不能将这些浮点目标值发布为上界。

- [Rdwalk 日志](runs/solver_diagnostics_20261103/rdwalk_t400/analyses/assertion_violation/degrees/1/c-001/attempts/001/solver.log)
- [2DWalk 日志](runs/solver_diagnostics_20261103/2dwalk_x1000_y10/analyses/assertion_violation/degrees/1/c-001/attempts/001/solver.log)

除此以外，针对**当前实现强制的固定正下界** `η≥δ=10^-6` 和固定 `c<1`，可以直接说明这两个程序为何不适合有限次多项式全局收缩模板：

若从状态 s 开始，前 N 个 CFG 转移必定仍处于普通状态，反复应用 `E[η_next]≤cη`，有

`η(s) ≥ c^(-N) E[η(S_N)] ≥ δ c^(-N)`。

- Rdwalk 可到达循环头状态 `(x,t)=(-N,N)`（连续向下走 N 次）。从这里退出需要把 x 提升到 100，每次最多增加 1，因此至少 N 个后续转移不会到达终端。沿这些状态，任何固定次数的 `η(x,t)` 只按 N 的多项式增长，无法在所有 N 上大于 `δ c^(-N)`。
- 2DWalk 可到达 x、y 都随 N 增大的循环头状态。退出需要 y<1 或断言违反 x<1，且每次更新最多降低一个坐标 1，因此同样存在至少 N 步必不终止的状态族，得到相同矛盾。

这是对**本项目当前证书条件**的限制分析，不是对程序真实违反概率的结论，也不是对论文指数模板的反证。仅增加多项式次数或多尝试几个严格小于 1 的 c，不能消除上述渐近矛盾。后续若要覆盖这些程序，需要改变证书族/正性要求/规则；本次没有擅自改变已经确定的 §2.2 主体路线。

## 3. Race、Prspeed、原文 RdAdder：精确证书重建或预算

Race 的初始搜索得到浮点候选，但有理数重建后出现负的非负乘子或非 PSD 的 Gram 块。修复没有全部成功。例如 [Race x=40 的重建记录](runs/baseline_20261103/race_x40_y0/analyses/assertion_violation/degrees/1/c-001/attempts/001/verification.json)。扩大 c/次数/编码搜索后，x=35、40 的候选通过精确复核，但最终概率界截断为 1，不能当作有用的小概率结果。

Race x=45、Prspeed T>150、T>250 的加大预算运行在 120 秒时被外层进程预算终止。最后已写出的阶段为 `solver.json`，其中 MOSEK 为 `optimal`，还没有生成相应的最终精确证书；因此定位为浮点求解后的认证阶段未完成，不能宣称是单纯的 MOSEK 求解超时。Prspeed T>200 的加大预算搜索结束于 `time_budget`，未找到证书。

原文 RdAdder 实际违反概率为 0，因为 x≤100，而断言只要求 x≤200。本次通用合成仍没有重建出可验证证书；这说明搜索/数值认证不完备，不能由此推出断言可能失败。

## 4. Hardware：事件方向、标志域和剩余数值问题

M1DWalk、Newton、Ref 的目标都是**成功完成**。论文求下界，本分支求上界。最终输入保留原循环和所有独立硬件存活检查。

`exit` 降为布尔标志时，单独使用区间 `0≤alive≤1` 会引入中间的实数状态；闭包处理还可能让边界处同时进入 guard 的两侧。最终输入用 0.5 分隔 0/1，并显式保留 `alive=0 or alive=1` 的源不变量，包括语法上不可达的分支，避免把标志边界的伪循环归因于原程序。这个不变量来自唯一的两种标志赋值，不是新增执行假设。

布尔域完善后，Newton 三例成功：p=0.0005、0.001、0.0015 对应的上界分别为 **0.8473107067514187、0.6484767027543494、0.5054730699839308**，全部通过独立精确复核。它们仍是成功事件的上界，不能拿来替代论文下界。

M1DWalk 与 Ref 的最终结果见结果表。M1DWalk 还存在可定位的 c 选择限制：当前 CFG 的无故障一轮有 4 个转移，存活概率为 1-p。在 x 任意负的状态族上，迭代收缩与正下界推出 `η(s) ≥ δ ((1-p)/c^4)^N`。因此，若 `c^4 < 1-p`，有限次多项式同样无法满足全局条件。基础配置 c=0.9999 对这三个 p 都触发该障碍；对 p=0.0001 另试 c=0.99999，以排除这一具体障碍；该次仍未取得可验证证书，结果保留在 `retry_boolean_20261103`。去掉该障碍不保证数值搜索必然成功。

Ref 的基础配置在构造二次模板时耗尽 25 秒总预算，尚未进入该次 MOSEK 求解；其中 `unknown` 是搜索记录的未完成状态，不能解读成一次 MOSEK infeasible。对 p=0.00001 的最终布尔域输入另行执行较大预算搜索：c=0.99999 时 MOSEK 得到浮点 optimal，但在后续精确认证阶段耗尽 120 秒进程预算。逐次状态见当前源程序对应的 `results.json` / `solver.json`。历史区间版的 Newton/Ref 诊断也报告过 UNKNOWN；历史 Ref 的三次模板还出现过 `Complete model exceeds variable budget`。这些旧编码结果仅用于定位，不计入当前输入的结果。最终结果不将“没有证书”解释为成功概率为 0，也不把任意一次数值 infeasible 推广为所有模板均不可行。

## 实验范围

- 所有输入使用相同的生产 assertion_violation 流程和原后端，未修改已有模块。
- 基础搜索只覆盖次数 1–2、c=0.9999；有选择地扩大到次数 1–3、c=0.999/0.99999。具体配置在 README 和 runner 中。
- 汇总按源 SHA-256 匹配，修改前的盒约束/标志编码运行保留作诊断，绝不冒充最终版本结果。
- 未收录的 RdAdder 偏差、Robot、Coupon 参数实例见 SOURCE_NOTES；它们未计入成功率分母。
